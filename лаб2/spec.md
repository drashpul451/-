# Специфікація вимог та Use Cases — Електронна Бібліотека (E-Library System)

## 1. Актори та Ієрархія Ролей

### Користувачі (Люди)
- **Guest (Гість)**: Базовий неавторизований відвідувач. Може шукати книги в каталозі (`UC-01`), опціонально фільтрувати їх за авторами чи роками видання (`UC-02`) та проходити авторизацію (`UC-03`).
- **User (Читач / Користувач)**: Авторизований користувач системи (**успадковує всі можливості `Guest`**: `Guest <|-- User`). Може переглядати власну історію видач (`UC-04`), подавати запит на бронювання книги (`UC-05`) та скасовувати його (`UC-06`).
- **Librarian (Адміністратор / Бібліотекар)**: Авторизований співробітник бібліотеки (**успадковує всі можливості `User`**: `User <|-- Librarian`). Може додавати нові книги та авторів (`UC-07`), фіксувати повернення книг (`UC-09`) та керувати каталогом.

### Зовнішні системи та сервіси (`<<System>>`)
- **Notification Service (Сервіс сповіщень)**: Зовнішня система зі стереотипом `<<System>>`, якій делегується (`<<delegate>>` від `UC-10`) асинхронна відправка нагадувань на `User.email` про наближення або прострочення терміну повернення книги (`Loan.due_date`).

## 2. Перелік Прецедентів (Use Cases)

| ID | Назва Use Case | Актор | Опис |
|---|---|---|---|
| **UC-01** | Пошук та перегляд каталогу | Guest | Базовий перегляд книг та авторів у каталозі. |
| **UC-02** | Фільтрація за автором/роком | Guest | Опціональне розширення (`<<extend>>` до UC-01) для точного пошуку. |
| **UC-03** | Авторизація (Log In) | Guest | Вхід у систему. Виступає **Precondition** для дій авторизованих ролей. |
| **UC-04** | Перегляд історії Loan | User | Перегляд списку своїх активних та минулих бронювань. |
| **UC-05** | Створення запиту на Loan | User | Подача запиту на видачу книги (з перевіркою боргів за ADR 0002). |
| **UC-06** | Скасування бронювання | User | Опціональне скасування (`<<extend>>` до UC-05) непідтвердженого запису. |
| **UC-07** | Додавання Book та Author | Librarian | Створення нових записів книг та авторів у каталозі. |
| **UC-08** | Перевірка унікальності ISBN | Librarian | Обов'язкова валідація (`<<include>>` у UC-07) коду ISBN. |
| **UC-09** | Підтвердження повернення книги | Librarian | Фіксація дати повернення (`returned_at = NOW()`) та закриття Loan. |
| **UC-10** | Формування сповіщень про борги | System | Системний процесс, що передає (`<<delegate>>`) дані сервісу `Notification Service`. |

---

## 3. Основні цілі
1. Забезпечити зручний та швидкий пошук книг у каталозі бібліотеки.
2. Автоматизувати процес бронювання та обліку видачі книг (`Loan`) з чітким контролем термінів повернення та заборгованостей.
3. Гарантувати дотримання цілісності даних відповідно до концептуальної ER-моделі (3NF), створеної у Лабораторній роботі №1.

---

## 4. Зв'язок із моделлю даних (Лабораторна робота №1)
Усі вимоги та прецеденти спираються на сутності та атрибути з `lab1/spec.md` та `lab1/diagram.mmd`:
- **User**: `id` (UUID), `email`, `full_name`, `created_at`.
- **Author**: `id` (UUID), `name`, `bio`.
- **Book**: `id` (UUID), `title`, `isbn`, `published_year`.
- **Loan**: `id` (UUID), `user_id` (FK), `book_id` (FK), `borrowed_at`, `due_date`, `returned_at`.
